# LIMITS — what these numbers do not license

Generated by hand, unlike `REPORT.md`, because its job is to constrain claims rather
than restate measurements. Every figure here is read from an artefact under `runs/`
or `baselines/`; where a number does not exist, the row says so.

Read this before quoting anything from the README or `REPORT.md`.

---

## 1. The ceiling on every headline number

**External French data is now in use — at component level.** Since 2026-10-21
`make frbench` scores the linker (XNLI-fr), the reader (MASSIVE-fr) and retrieval
(MIRACL-fr, pooled) against human annotations this repo did not author — verdicts in
`docs/REPORT.md` §6d, DECISIONS D-022. **The pipeline-level headline — temporal
correctness@1 — is still internal-validity only**: the relation layer's gain was
earned on data whose gold labels the same generator authored, and no external
corpus here carries supersede chains. Closing that specific gap is the SUMM-RE
hand-labelled set: annotation work, not a download. Two further ceilings: external
arms run in the e5 embedder space while the synthetic headline runs in the hash
baseline's — arms may be compared **within** one bench, never across benches; and
the external corpora supply *relation* and *relevance* labels, not bi-temporal
supersede gold. The guide asks for exactly this honesty
(7.2: synthetic conversations are allowed but "must be complemented by an evaluation
that avoids measuring only the model's ability to recognise formulations generated by
the same patterns"). The complement — a hand-labelled excerpt set from a public
corpus — is **not done**. See `docs/BLOCKERS.md`.

The failure mode is not hypothetical. The fine-tuned embedder raised its own metric
to **1.0** hard-negative accuracy and *lost* the headline (0.6286 → 0.5429 dev
temporal@1, DECISIONS D-013): it got better at distinctions its own templates
contain. A synthetic corpus can be scored into agreement.

## 2. Statistical limits

| Limit | Measured |
|---|---|
| Bootstrap CIs resample **projects**, and the test split holds ~4 projects at 20-project scale | so the intervals are wide and the effective n is small; treat them as indicative |
| Seed-to-seed spread on the headline | **0.1714**, against a mean effect of +0.3077 — the effect is larger than the spread, but not by much |
| Split ratios at small project counts | `assign()` guarantees ≥1 project per bucket, so a 6-project run yields 4/1/1: dev and test are single projects and the numbers are not comparable to the 20-project canonical run |
| Person names are **not** disjoint across splits | 16 names appear in more than one split at 20 projects (recorded in the manifest's `leakage.persons`). The guide asks for unseen people only "si possible"; this generator does not deliver it, so no claim here may say the test set holds out persons |
| The split manifest is shared mutable state | rewritten by whichever run last touched `data/splits/ledger.json`, at that run's project count |

## 3. Where the relation layer is weak — named, not averaged

The stage artefacts report a confusion matrix over **predicted edges**, and the two
splits disagree enough that quoting one of them would mislead. Both are below
(20 projects, seed 42, rules linker; `runs/stage_linker_{dev,test}_42/result.json`):

| measure | dev | test | reading |
|---|---|---|---|
| `supersedes` precision / recall | 0.5172 / 0.7143 | **0.88 / 0.8462** | the load-bearing relation; below the 0.95 precision target on both splits, and far better on test than dev |
| `relation_macro_f1` (5 writable relations) | 0.2137 | 0.4169 | weak overall, on either split |
| `false_edge_rate` | 0.3312 | 0.3388 | **~1 in 3 written edges sits on a pair the ledger calls *unrelated*** — stable across splits, so not a sampling artefact |
| gold `contradicts` → predicted `supports` | 53 of 59 | — | **contradiction is the weakest label**: the linker calls a contradiction a confirmation |
| false `supersedes` edges | 14 | 3 | |
| guard refusals | 8 | 12 | |

The dev/test spread on `supersedes` precision (0.52 vs 0.88) is itself a finding: at
4 holdout projects per split, relation metrics are split-sensitive and a single
number should not be quoted as *the* linker quality.

Two honest qualifications. First, `supports` and `contradicts` edges do not drive
temporal correctness — only `supersedes` demotes evidence, and that path is guarded
by G0–G12 and measured separately. Second, the matrix covers only pairs with exactly
one gold label (100 of 154 edges on dev), and its coverage is reported beside it for
that reason. But the shape of the failure is clear: **the engine is a supersede
detector with a weak contradiction detector attached**, and any claim about
"explaining what changed" inherits that.

## 4. Abstention and the never-invent rules

| claim | status |
|---|---|
| No e-mail address is invented | **holds by construction and by test** — the address comes only from `data/contacts.json`; a known person without one is `email_missing`. Note the defect found by executing the code: `candidates()` used to answer *any* attribute with the budget owner's real address (DECISIONS D-019). Fixed, and pinned. |
| A hypothesis never triggers an action | holds — 5 adversarial cases pass, `hypothesis → action rate = 0` |
| Nothing is ever executed | holds — `needs_confirmation=true`, `executed=false`, asserted in the e2e suite |
| Unsupported-claim rate | **0.0 over 57 claims** on the §13 fixture. Small denominator, deterministic check (evidence-in-claim), not an LLM judge |
| Abstention on unanswerable questions | **9 of 12** — three leak (`unanswerable-2`, `-3`, `-9`): the system answers with real but irrelevant quotes. This is the worst current failure mode (B-08) and it is *not* fixed |
| Recipient resolution | **Measured, and the denominators are tiny.** Of 7 labelled cases: 5 had an ambiguous owner and **all 5 refused to commit** (justified abstention 5/5); 2 committed to a person and both were right (P@1 2/2, false-recipient rate 0.0). The abstention figure carries some weight; **P@1 over 2 cases is not a number to quote** — it is a smoke test that the path resolves at all. `runs/e2e/result.json` holds all of it |

## 5. Cost and latency

- Cold start and steady state are reported **separately**. The first query in a
  process pays CUDA context init and lazy model construction; averaging it into the
  percentiles once priced the cross-encoder at ~78× the baseline when it is ~16×.
- The cross-encoder reranker raises the headline (System B 0.5518 → 0.6616, 3/3
  significant on dev *and* test) and is **opt-in**, because it costs ~4× steady
  latency, 2182 MiB VRAM and ~9 s of cold start. Promotion is a deployment decision
  with a stated price, not a default.
- The `overlap` reranker variant is strictly *worse* than doing nothing. Kept as an
  ablation row so nobody re-introduces it as a "cheap" option.

## 6. Trained components: fitted, measured, not shipped

Reader, linker and embedder are all trained and all measured. None is the default,
because none beats the rules baseline on the headline metric (0.4 says the measured
baseline stays until a trained version beats it). The trained linker additionally
**has never run inside the engine end-to-end**: `build_linker` could not construct it
until D-019, so §10's logreg row is unmeasured (B-09). Its offline scores (dev F1
0.6981, test F1 0.7328) are classifier metrics, not system metrics.

## 7. Concept attention (M5): built; the synthetic bar undecided, the external check lost

Measured base vs refined from one code path, differing only in the vector column
(`like_for_like: true`, 3 seeds, 20 projects, dev): temporal@1 **0.5092 → 0.4991,
−1.01 pts** against a +3 pt bar.

This is **not** a refutation, and the reason is arithmetic rather than a rule. The
**base arm's own** residual headroom — the only denominator 6.13's bar is measured
against — is **0.69 pts on dev**, so a +3 pt gain was unreachable on the deciding
split.

An earlier draft of this file cited "22.1% headroom on test" to argue the bar could
be settled there. That number belongs to the **unscoped** arm (`a_scoped`), not to
System B, and quoting it was a denominator error: the bar is defined as a gain *over
System B*, so only System B's remaining failure counts. Measured correctly, test
leaves **4.91 pts on average — but 2.04 / 10.42 / 2.27 pts per seed**, meaning only
one of three seeds could carry a +3 pt gain at all. The mean is an artefact of that
seed, and `concept_gate`'s `decidable` check tests the mean, so it would report
`decidable: true` on test while two of three seeds cannot measure the bar.

So the blocker is not "9.5 forbids deciding on test" — it is that **this corpus does
not contain three points of temporal failure left for a geometry change to fix**, on
either split. Settling 6.13 needs more temporal churn in the corpus (more projects or
more supersede chains per project), not a different rule. `concept.enabled` stays
false; 6.13 stays untested (B-06).

**Later the same day, the mechanism claim was tested where it could win — and lost
(D-022, §6d).** On the MIRACL-fr judged pool (343/343 questions, 3,407 human-rated
candidates, real room at rank-1), refining the stored vectors — anchoring holding on
the real store (cosine-to-base 0.9853, drift p95 0.1763) — moved MRR@10 0.6965 →
0.6774 dense and 0.6046 → 0.5898 hybrid: **−1.5 to −1.9 pts**. Same queries, same
pool, same fusion; only the stored column moved. "Context-refined vectors rank
better" is now measured false on real French, while the temporal number 6.13 was
phrased around remains untestable outside this synthetic corpus. Both facts travel
together: the drop is evidence, not indecision.

The engineering result that *is* solid: a refined vector must be a small perturbation
of its base, or retrieval silently breaks. A replacing head produced cosine-to-base
**0.0105** — an unanchored space that still returned 5 plausible-looking hits per
query. The refine job now **refuses to publish** an unanchored column, and the bound
is structural (a capped residual), because a soft penalty was measurably outbid.

## 8. Unmeasured, by name

- **MTEB-French anti-forgetting gate**: not installed, so `eval/regression_mteb.py`
  writes `gate: unmeasured` and refuses to substitute the MASSIVE pairwise proxy for
  nDCG@10. A proxy is reported *as* a proxy.
- **Embedder bake-off** across candidates: only `multilingual-e5-base` and
  `Qwen3-Embedding-0.6B` measured against the hash baseline.
- **§10 rows 3, 8, 11**: need a real embedder, not the offline hash stand-in.
- **Population-scale recipient accuracy**: the false-recipient rate is 0 forced
  guesses across the fixture's clarify cases — that is fixture scale, not a claim
  about real traffic.
- **PDF/DOCX dossier export**: not implemented (the guide lists it as optional).

## 9. Licensing limits

Five corpora are now downloaded, each pinned to a repo revision in
`data/external/*/PROVENANCE.json` with the licence **as the card states it**:
SUMM-RE `cc-by-sa-4.0` (so the eventual hand-labelled excerpt set is a derivative
work and shares under the same licence), MASSIVE canonical `cc-by-4.0` (the earlier
"conflict" was the mteb mirror stating apache-2.0), the official `miracl/*` repos
`apache-2.0` (the guide's named MIRACL repo is a stub), mMARCO/LightOn/NanoMTEB
resolved with cards that state no licence. **XNLI's card states none at all** — used
here for evaluation only, nothing derived from it is redistributed, and no licence
is ever back-filled from the guide's claim. `docs/DATASETS.md` is generated and
regenerated from the live API, so this section is the interpretation and the file is
the evidence.
